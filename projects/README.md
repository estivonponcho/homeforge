# Projects & Builds

Real builds from the workbench. This is the authority layer of [HomeForge](../README.md):
anyone can list gear, but *"here's the thing I actually built with it"* is what
earns trust — and what turns a reader into an email subscriber and a buyer.

Each build write-up ends with a **Gear used** list that links to the relevant
[picks](../README.md) (which carry the affiliate links). Projects → proof → picks
→ pier. That's the funnel.

## The builds

- [Wi-Fi Thermal Receipt Printer](esp-thermal-printer.md) — an ESP8266 web
  "message board" that prints notes on a thermal printer, timestamped and
  correctly oriented as the paper feeds out.
- [The Quadra: a 3-watt homelab node](quadra-homelab-node.md) — a sub-$100 ARM
  box doing real always-on work on a private mesh network.
- [Flipper Zero + hardware hacking](flipper-and-hardware-hacking.md) — custom
  firmware, a curated toolkit, and hands-on microsoldering.
- [Custom apps & health integrations](custom-apps-and-health-integrations.md) —
  building full software (incl. a private, self-hosted health-data hub) when the
  app you want doesn't exist.

## A note on safety & privacy

These write-ups are deliberately **scrubbed**: no Wi-Fi credentials, no private
IP addresses, no keys, no ports, no console-specific piracy details. That's not
just caution — *showing that you handle security responsibly is itself a
credibility signal* to the kind of reader who runs their own infrastructure.

## How to add a build

1. Do the thing. Take a few photos as you go (photos massively lift these posts).
2. Drop a `.md` file here following the format of the existing ones:
   **what it does → why → how (the interesting parts) → what I'd change → gear used.**
3. Link every piece of gear to its [pick](../README.md).
4. Add it to the list above and feature the best one on the site.
